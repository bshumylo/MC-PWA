# MC PWA

**Перетворіть EspoCRM на застосунок, який користувачі можуть встановити на телефон чи комп'ютер, з push-сповіщеннями та нижньою панеллю навігації.**

[English](README.md) · Українська

Версія **1.3.2** · EspoCRM **≥ 10.0.0** · PHP **≥ 8.3** · AGPL-3.0

## Що це робить

- **Застосунок, який можна встановити.** Користувачі можуть додати EspoCRM на головний екран (Android, iPhone з iOS 16.4 або новішою, Chrome чи Edge на комп'ютері). Назву, коротку назву, кольори та іконку задає адміністратор.
- **Push-сповіщення.** Призначення, отримані листи, згадки, пости стрічки, повідомлення та системні сповіщення приходять на пристрій, навіть коли браузер закрито. Спливні нагадування про зустрічі, дзвінки й завдання теж надходять як push. Бібліотеки Composer не потрібні.
- **Нижня панель навігації.** Панель кнопок унизу екрана, як у «рідному» застосунку. Кнопки обираєте ви: вкладки сутностей або власні посилання. Користувачі бачать лише ті кнопки, до яких мають доступ.
- **Особисті налаштування push.** Кожен користувач обирає, які сповіщення отримувати, і може задати «тихі години» (меню користувача → *Push Notification Settings*).
- **Прості перевірки.** *Send Test Push* перевіряє доставку. *Diagnostics* показує стан push одним поглядом. *Rotate VAPID Keys* створює нові ключі.
- **Автоматичне прибирання.** Щоденне завдання видаляє непрацюючі push-підписки та старі записи про встановлення.
- **Ярлики застосунку.** Швидкі дії з іконки застосунку.
- **Необов'язкова статистика встановлень.** Типово вимкнена. Лише анонімні дані: випадковий ідентифікатор, тип пристрою, платформа й версія ОС. Жодних даних користувачів.

## Вимоги

- EspoCRM 10.0.0 або новіша.
- PHP 8.3 – 8.5 з розширеннями `openssl`, `curl` і `gd`.
- HTTPS. Браузери вимагають його для service worker і push.
- Працюючий cron (або daemon) EspoCRM. Він потрібен для доставки push-сповіщень.

## Встановлення

1. Завантажте `mc-pwa-1.3.2.zip` зі сторінки [Releases](../../releases/latest). Не беріть автоматичний файл «Source code (zip)»: його не можна встановити.
2. В EspoCRM відкрийте **Адміністрування → Розширення → Завантажити**, оберіть ZIP і натисніть **Встановити**. Інсталятор сам перебудовує систему. **Адміністрування → Rebuild** потрібен лише тоді, коли щось працює не так.
3. Відкрийте **Адміністрування → PWA → PWA Settings**. Увімкніть PWA та, за бажанням, push-сповіщення й нижню панель навігації.

Ключі push (VAPID) створюються автоматично під час встановлення. Приватний ключ лишається на вашому сервері. Публічний ключ показано в адмін-панелі лише для читання.

## Оновлення

1. Зробіть резервну копію бази даних і файлів.
2. Встановіть новий ZIP поверх старого (**Адміністрування → Розширення → Завантажити → Встановити**).
3. Примітки до версій:
   - З **1.0.x**: кнопки нижньої панелі, збережені у старому форматі, перетворюються автоматично.
   - **1.3.2**: жодних ручних кроків. Інсталятор сам перебудовує систему. Починаючи з цієї версії, коли інший користувач відкриває застосунок на спільному пристрої, стару підписку замінює підписка для нового користувача (див. «Безпека»).

## Налаштування

Відкрийте **Адміністрування → PWA → PWA Settings**.

| Налаштування | Що робить |
|---|---|
| PWA Enabled | Дозволяє користувачам встановлювати EspoCRM як застосунок. |
| App Name / Short Name | Назви на пристрої. |
| Theme / Background Color | Кольори застосунку та його стартового екрана. |
| App Icon | Квадратний PNG, бажано 512×512. Якщо порожньо, береться логотип компанії. |
| Push Notifications Enabled | Надсилає системні сповіщення як push. |
| Push Notification Types | Assignment, Email Received, Message, Stream Post, Mention, System. |
| Bottom Navigation Bar Enabled | Показує панель кнопок у встановленому застосунку на мобільних пристроях. Типово вимкнено. |
| Show Button Labels | Текст під іконками. Коли вимкнено, показуються лише трохи більші іконки. |
| Bottom Bar Buttons | До 8 кнопок (рекомендовано 3–5): вкладки сутностей або власні посилання. Порядок змінюється перетягуванням; кнопки-посилання редагуються іконкою олівця. |
| Installation Statistics Enabled | Анонімна статистика встановлень. Типово вимкнено. |
| Installation Retention (days) | Записи про встановлення, не бачені стільки днів, видаляє щоденне прибирання. 0 зберігає їх назавжди. Типово 365. |
| Push Subscriptions Enabled | Дозволяє пристроям реєструвати push-підписки. Типово увімкнено. Коли вимкнено, нові підписки не зберігаються; наявні лишаються. |
| Max Delivery Failures | Підписку видаляють після стількох невдалих доставок поспіль. 0 вимикає видалення. Типово 10. |

У розділі **PWA** сторінки Адміністрування також є два списки: **PWA Installations** (анонімна статистика) і **PWA Push Subscriptions**. Для кожної підписки видно останню успішну доставку, останню помилку та кількість невдач поспіль.

На сторінці налаштувань є кнопки *Send Test Push*, *Diagnostics* і *Rotate VAPID Keys*. Ротація ключів видаляє всі підписки; пристрої підписуються знову автоматично, коли застосунок відкрито наступного разу. *Diagnostics* показує ключі, кількість підписок (і скільки з них мають помилки), останній запуск завдання нагадувань, перевірку `openssl`/`curl`/`gd` у PHP та останні помилки доставки.

**Параметр файлу конфігурації.** `pwaPushExtraHosts` (лише в `data/config.php`) — список додаткових імен хостів push-сервісів. Типово порожній. Залишайте його порожнім, якщо вам реально не потрібен інший push-сервіс.

**Про нижню панель.**

- Вона з'являється лише у встановленому застосунку, на екранах вужчих за 768 px. Щоб перевірити її у звичайній вкладці браузера, виконайте в консолі браузера `localStorage.setItem('mcPwaBottomBarForce', '1')` і перезавантажте сторінку. Потрібно бути залогіненим.
- Кнопки сутностей беруть іконку, колір і назву із сутності. Вони приховані від користувачів без доступу до цієї сутності. Кнопки-посилання можуть мати область доступу (scope), позначку «лише для адміністратора» та відкриття в новій вкладці.

**Заплановані завдання.** Обидва створюються автоматично: *McPwaSendReminderPush* (щохвилини) і *McPwaCleanup* (щодня о 03:30).

## Безпека

- **Спільні пристрої.** Push-підписка належить браузеру, а не сесії входу. Застосунок скасовує підписку пристрою, коли користувач виходить. Якщо сесія просто закінчилася, пристрій і далі отримує сповіщення попереднього користувача, доки хтось не вийде там, інший користувач не відкриє там застосунок або адміністратор не видалить підписку. На спільних комп'ютерах завжди користуйтеся *Вийти*.
- **Що показує сповіщення.** Push може містити назви записів, теми листів і короткий фрагмент поста стрічки (лише те, що користувач має право читати). Операційна система може показати це на екрані блокування. Якщо пристрій загублено, видаліть рядки користувача в *PWA Push Subscriptions*.
- **Публічні файли.** Web manifest і клієнтська конфігурація публічні, бо браузери завантажують їх без входу. Вони містять назву застосунку, кольори, мову, увімкнені функції PWA, публічний ключ push і типи сутностей *Quick Create* (як ярлики). Не давайте конфіденційних назв цим сутностям.
- **Ключі.** Приватний ключ push зберігається у внутрішній конфігурації й ніколи не передається через API. Його створюють для кожного встановлення; секретів у репозиторії немає.
- **Приватність.** Статистика встановлень анонімна й типово вимкнена. Push-підписки можна вимкнути окремо. Зберігається не більше 5000 записів про встановлення.
- **Контактна адреса.** Як вимагає стандарт Web Push, токен push містить контактну адресу: системну адресу вихідної пошти (або URL сайту, якщо її не задано).

Щоб повідомити про вразливість, див. [SECURITY.md](SECURITY.md).

## Для розробників

**Локальна збірка ZIP.** Розширення використовує офіційний шаблон.

```bash
npm install
node build --all        # повний сайт для розробки
node build --extension  # інсталяційний ZIP у build/ (mc-pwa-<version>.zip)
npm run sa              # статичний аналіз (phpstan)
npm run unit-tests      # unit-тести (phpunit)
```

Серверний самотест шифрування Web Push — `tests/webpush-selftest.php`. Ручний чекліст QA — `tests/manual-checklist.md`.

**Релізи.** Підвищте версію в `extension.json` і `package.json` та злийте зміни в `main`. Workflow [.github/workflows/release.yml](.github/workflows/release.yml) сам створить реліз `vX.Y.Z` з `mc-pwa-X.Y.Z.zip`. Історію змін див. у [CHANGELOG.md](CHANGELOG.md).

**Як це працює.**

- Публічні точки входу (GET): `pwaManifest`, `pwaServiceWorker`, `pwaIcon`, `pwaConfig`. Manifest, service worker та іконки генеруються з налаштувань.
- API (потрібен вхід): `GET /McPwa/bottomBar`. Лише для адміністратора: `GET /McPwa/status`, `POST /McPwa/rotateVapid`. Із заголовком `X-Requested-With` (захист від CSRF): `POST /McPwa/subscription`, `POST /McPwa/stats`, `POST /McPwa/testPush`.
- Хук на `Notification` (після збереження) ставить у чергу завдання, яке шифрує й надсилає push через `Classes/Push/WebPushSender` (RFC 8291 `aes128gcm`, VAPID RFC 8292 `ES256`, чистий PHP). Усі доставки проходять через `Classes/Push/Dispatcher`, який записує результат і видаляє прострочені (404/410) підписки.
- Конфігурація нижньої панелі віддається лише залогіненим користувачам. Кнопки розв'язуються на сервері (назва, іконка, колір, доступ) для поточного користувача й мови, а кожне значення (URL, клас іконки, колір) перевіряється й очищується. Браузер малює панель через DOM API (без `innerHTML`) з `rel="noopener noreferrer"` для зовнішніх посилань.

**Деталі безпеки.**

- `testPush` працює лише з підписками самого користувача, раз на 30 секунд (нову підписку можна перевірити через 30 секунд після створення).
- Захист від SSRF: endpoint push має бути простим URL `https://host[:443]/path` (без user-info, зворотної скісної риски, фрагмента, IP-адреси чи іншого порту) на відомому push-сервісі (Google, Mozilla, Microsoft, Apple). Перед надсиланням хост розв'язується й відхиляється, якщо вказує на приватну, loopback, link-local або зарезервовану адресу. З'єднання прив'язується до перевіреної публічної IP на порту 443 (захист від DNS rebinding). `pwaPushExtraHosts` розширює дозволений список.
- Власність: користувач може видалити лише власну підписку, а endpoint, що належить іншому акаунту, ніколи не переприв'язується мовчки.
- Усі вхідні дані (ключі, endpoint-и, ідентифікатори, кольори, класи іконок, мітки) суворо перевіряються.
